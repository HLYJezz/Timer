# ⏱ ฐานเวลา (Base Timer)

จอเวลากลางสำหรับ **ฐานกิจกรรม** — ทุกคนเห็นพร้อมกันว่าฐานไหนเหลือเวลาเท่าไหร่ และ **ฐานไหนเกินเวลาไปกี่นาที** จะได้ไม่ต้องวิ่งไปดูเองทีละฐาน

A live shared countdown board for camp activity stations. No npm dependencies.

**ใช้ได้ 2 แบบ — เลือกอันเดียว**

| แบบ | เหมาะกับ | ต้องเตรียม |
|---|---|---|
| 🌐 **[GitHub Pages + Firebase](#ขึ้น-github-pages-แนะนำ--ใช้ผ่าน-4g-ได้-ไม่ต้องพึ่ง-wi-fi-ค่าย)** | งานจริง ใช้ผ่าน 4G ได้ ไม่ต้องมีโน้ตบุ๊กเปิดค้าง | บัญชี Google (ฟรี) ตั้งครั้งเดียว ~10 นาที |
| 💻 **[รัน `server.js` เอง](#เริ่มใช้-บนโน้ตบุ๊กเครื่องเดียว--wi-fi-เดียวกัน)** | ลองเล่น หรือค่ายที่มี Wi-Fi วงเดียวกันแน่ ๆ | ติดตั้ง Node.js บนโน้ตบุ๊ก 1 เครื่อง |

## ปัญหาที่แก้

| เดิม | หลังใช้ |
|---|---|
| ไม่รู้ว่าฐานไหนช้า ต้องวิ่งไปดู | จอรวมขึ้นสีแดง + บอกว่าเกินไปกี่นาที |
| ฐานเสร็จแล้วแต่ฝ่ายกลางไม่รู้ | ฐานกด "เสร็จแล้ว" ขึ้นจอทันที |
| อยากบอกฝ่ายกลางว่าติดอะไร ต้องโทร | ปุ่ม 🆘 + ช่องพิมพ์ข้อความสั้น ๆ |
| แจ้งทุกฐานพร้อมกันไม่ได้ | ประกาศจากฝ่ายกลางเด้งทุกเครื่อง |

## เริ่มใช้ (บนโน้ตบุ๊กเครื่องเดียว + Wi-Fi เดียวกัน)

ต้องมี [Node.js 18+](https://nodejs.org) ก่อน (โหลดตัว LTS แล้วกด Next รัว ๆ)

```bash
node server.js
```

เทอร์มินัลจะพิมพ์ลิงก์ออกมา เช่น `http://192.168.1.42:3000` — เอาลิงก์นั้นส่งให้ทีมในกลุ่มไลน์ ทุกคนต้องต่อ **Wi-Fi วงเดียวกัน**

ตั้ง PIN กันคนอื่นมากดสั่งรอบมั่ว:

```bash
ADMIN_PIN=1234 node server.js
```

บน Windows PowerShell:

```powershell
$env:ADMIN_PIN="1234"; node server.js
```

## ขึ้น GitHub Pages (แนะนำ — ใช้ผ่าน 4G ได้ ไม่ต้องพึ่ง Wi-Fi ค่าย)

GitHub Pages เสิร์ฟได้แต่ไฟล์นิ่ง ๆ **รัน `server.js` ไม่ได้** ถ้าเอาขึ้นเฉย ๆ ทุกเครื่องจะแยกกันจับเวลาของตัวเอง ซึ่งไม่ได้แก้ปัญหาอะไรเลย

เลยต้องย้าย "ที่เก็บเวลาที่ทุกคนใช้ร่วมกัน" ไปไว้ที่ **Firebase Realtime Database** (ฟรี ขนาดนี้ไม่มีทางเกินโควตา และไม่มีอาการหลับเหมือน Render)

### 1. สร้าง Firebase

1. ไปที่ [console.firebase.google.com](https://console.firebase.google.com) → **Add project** → ตั้งชื่ออะไรก็ได้ → ปิด Google Analytics ได้ ไม่ต้องใช้
2. เมนูซ้าย **Build → Realtime Database** → **Create Database**
3. เลือก location **`asia-southeast1` (Singapore)** — ใกล้ไทยที่สุด ตอบสนองไวสุด
4. ตอนถามเรื่อง rules เลือกอะไรก่อนก็ได้ เดี๋ยวไปทับในข้อ 3

### 2. เอาค่า config มาใส่

ในหน้า Firebase กด ⚙️ **Project settings → General** → เลื่อนลงล่างสุด → **Your apps** → กดไอคอน **`</>`** (Web) → ตั้งชื่อ app → จะได้ code หน้าตาแบบนี้

เอาค่าที่ได้มาใส่ใน [`public/firebase-config.js`](public/firebase-config.js)

```js
window.FIREBASE_CONFIG = {
  apiKey: 'AIza......',
  authDomain: 'ชื่อโปรเจกต์.firebaseapp.com',
  databaseURL: 'https://ชื่อโปรเจกต์-default-rtdb.asia-southeast1.firebasedatabase.app',
  projectId: 'ชื่อโปรเจกต์',
  appId: '1:....:web:....'
};

window.ROOM_ID = 'medcamp-2569-x7k2vq';   // ← ตั้งให้เดายาก อ่านข้อ 4
```

> `databaseURL` บางทีไม่โผล่ในกล่อง config — ไปก๊อปจากหน้า **Realtime Database** ด้านบนสุดแทน
> `apiKey` ของ Firebase ฝั่งเว็บ **เปิดเผยได้ปกติ** ไม่ใช่ความลับ ตัวคุมสิทธิ์จริง ๆ คือ rules ในข้อถัดไป

### 3. ตั้ง Rules (อย่าข้าม)

**Realtime Database → Rules** ลบของเดิมทิ้ง วางอันนี้แทน แล้วกด **Publish**

```json
{
  "rules": {
    "rooms": {
      "$room": {
        ".read": true,
        ".write": true,
        ".validate": "newData.hasChildren(['stations'])"
      }
    }
  }
}
```

> ⚠️ **ห้ามใช้ "Start in test mode" แล้วปล่อยไว้** — rules แบบ test mode มีวันหมดอายุ 30 วัน พอถึงวันงานจริงอาจใช้ไม่ได้แล้ว ต้องวาง rules ข้างบนทับเอง

### 4. เรื่องความปลอดภัย ต้องเข้าใจก่อนใช้

rules ข้างบนแปลว่า **ใครก็ตามที่รู้ลิงก์เว็บ + รู้ `ROOM_ID` กดปุ่มได้ทุกปุ่ม** รวมถึงกดหมุนรอบและรีเซ็ตเวลา

- `ROOM_ID` คือรหัสผ่านกลาย ๆ ตัวเดียวที่มี → ตั้งให้มั่ว ๆ เช่น `medcamp-2569-x7k2vq` **อย่าใช้** `camp` หรือ `test`
- `ROOM_ID` อยู่ในโค้ดที่ push ขึ้น GitHub → **ถ้า repo เป็น public ใครก็เปิดดูได้** อยากกันจริงให้ตั้ง repo เป็น **private** (GitHub Pages ใช้กับ repo private ได้ในบัญชีฟรี)
- ในโหมด Firebase **`ADMIN_PIN` ไม่ทำงาน** เพราะไม่มีเซิร์ฟเวอร์ของเราคอยตรวจ ปุ่มอันตรายทุกปุ่มมีแค่หน้าต่าง "แน่ใจนะ?" กันกดพลาดเท่านั้น
- ข้อมูลในนี้มีแค่ชื่อฐานกับเวลา ไม่มีข้อมูลส่วนตัวใคร ความเสี่ยงจริง ๆ คือมีคนมือบอนมากดป่วน ไม่ใช่ข้อมูลรั่ว

### 5. เปิด GitHub Pages

push ขึ้น GitHub แล้วไปที่ repo → **Settings → Pages → Source: GitHub Actions**

ไฟล์ [`.github/workflows/pages.yml`](.github/workflows/pages.yml) จัดการที่เหลือให้เอง (มันเอาเฉพาะโฟลเดอร์ `public/` ขึ้น) แล้วจะได้ลิงก์แบบ

```
https://ชื่อผู้ใช้.github.io/ชื่อ-repo/
```

ส่งลิงก์นี้ในกลุ่มไลน์ได้เลย ใช้ได้ทั้ง 4G และ Wi-Fi

### เช็กว่าใช้ได้จริงไหม

เปิดเว็บ 2 เครื่อง ดูมุมขวาบน ต้องขึ้น **"เชื่อมต่อแล้ว · Firebase"** จุดสีเขียว
กดเริ่มเวลาที่เครื่องนึง อีกเครื่องต้องขยับตามภายใน 1 วินาที

ถ้าขึ้น "โหมดเครื่องเดียว" แปลว่า config ผิด → เปิด Console ในเบราว์เซอร์ดูข้อความ error

## ทางเลือกอื่น: Render (ใช้ `server.js` ตัวเดิม)

ถ้าไม่อยากยุ่งกับ Firebase — push ขึ้น GitHub แล้ว deploy ที่ [Render](https://render.com) เลือก **New → Blueprint** ชี้มาที่ repo นี้ (`render.yaml` ตั้งไว้ให้แล้ว) แบบนี้ `ADMIN_PIN` ใช้งานได้ตามปกติ

> ข้อเสีย: free tier ของ Render หลับเมื่อไม่มีคนใช้ ~15 นาที ตื่นครั้งแรกรอ ~30 วินาที ถ้าฐานกิจกรรมมีพักยาวระหว่างช่วง อาจเจออาการนี้บ่อย

## ใครเปิดหน้าไหน

| หน้า | ใคร | ทำอะไร |
|---|---|---|
| `/station.html` | พี่ประจำฐาน (มือถือ) | เลือกฐานตัวเอง กดเริ่ม / +5 นาที / เสร็จแล้ว / 🆘 |
| `/board.html` | ฝ่ายกลาง, จอโปรเจกเตอร์ | เห็นทุกฐานพร้อมกัน สีแดง = เกินเวลา |
| `/admin.html` | หัวหน้าฝ่ายกลาง | ตั้งชื่อฐาน/เวลา/กลุ่ม, เริ่มทุกฐานพร้อมกัน, หมุนรอบ, ประกาศ |
| `/` | ทุกคน | เมนูเลือกหน้า |

## จุดที่คิดมาให้แล้ว

- **เวลาอ้างอิงจากเซิร์ฟเวอร์** — รีเฟรช ปิดจอ แบตหมดแล้วเปิดใหม่ เวลาก็ยังตรง ไม่เพี้ยน
- **เน็ตหลุด** — หน้าจอยังนับต่อ และขึ้นสถานะ "สัญญาณหลุด" ให้เห็นชัด ถ้าต่อเซิร์ฟเวอร์ไม่ได้เลยจะสลับเป็น *โหมดเครื่องเดียว* ให้ใช้เป็นนาฬิกาจับเวลาธรรมดาได้
- **เซิร์ฟเวอร์ล่ม/รีสตาร์ต** — สถานะถูกเซฟไว้ที่ `data/state.json` เปิดใหม่แล้วรอบเดิมยังอยู่
- **จอไม่ดับ** ระหว่างใช้งาน (Wake Lock บนมือถือที่รองรับ)
- **เสียงเตือน** เหลือ 5 นาที / 1 นาที / หมดเวลา (บนจอรวมกดเปิดเสียงเองก่อน เพราะเบราว์เซอร์บล็อกเสียงอัตโนมัติ)
- **ปุ่มจอใหญ่** บน `/board.html` ขยายตัวเลขให้อ่านจากท้ายห้องได้

## เทสต์

```bash
node test.js
```

ตรวจเรื่องเวลาทั้งหมด — pause แล้วนาฬิกาต้องไม่เดินต่อ, ต่อเวลา, เกินเวลาเป็นค่าติดลบ, การหมุนกลุ่มแต่ละรอบ, แก้ตั้งค่าระหว่างเวลากำลังเดิน

## โครงไฟล์

```
server.js                 เซิร์ฟเวอร์ HTTP + SSE สำหรับใช้ใน Wi-Fi วงเดียวกัน (ไม่ใช้ dependency เลย)
test.js                   เทสต์เรื่องเวลา (node test.js)
public/reducer.js         โครงสร้างข้อมูล + คำสั่งทั้งหมด (ใช้ร่วมกันทุกที่)
public/app.js             ตัวเชื่อมต่อฝั่ง browser + ฟังก์ชันช่วยแสดงผล
public/sync-firebase.js   ซิงก์ผ่าน Firebase (สำหรับ GitHub Pages)
public/firebase-config.js ← ไฟล์เดียวที่ต้องแก้เวลาจะขึ้น GitHub Pages
public/board.html         จอรวม
public/station.html       หน้าพี่ประจำฐาน
public/admin.html         หน้าตั้งค่า/สั่งงานรอบ
data/state.json           สถานะล่าสุด (โหมด server.js เท่านั้น, สร้างอัตโนมัติ)
```

แอปเลือกวิธีซิงก์ให้เอง ตามลำดับนี้

1. **Firebase** ถ้ากรอก `databaseURL` ใน `firebase-config.js` แล้ว
2. **`server.js`** ถ้าเปิดเว็บจากเซิร์ฟเวอร์ที่รันอยู่
3. **โหมดเครื่องเดียว** ถ้าติดต่อไม่ได้ทั้งคู่ — ยังจับเวลาได้ แต่ไม่ซิงก์กับใคร

> ถ้ายังไม่ได้ตั้งค่า Firebase แอปจะไม่โหลด SDK ของ Firebase เลย ใช้ในค่ายที่ไม่มีเน็ตได้ไม่มีสะดุด

## API (เผื่ออยากต่อยอด)

- `GET /api/state` → `{ serverNow, state }`
- `GET /api/events` → SSE, event `state` และ `ping`
- `POST /api/action` → `{ type, ... }` เช่น `{"type":"station/start","id":"s1a2b3"}`

คำสั่งทั้งหมดอยู่ใน `public/reducer.js` ฟังก์ชัน `apply()`
